# 自动整理

一个面向日常办公归档和客户档案的 Windows 桌面程序。它在本机读取材料、识别字段、按客户自动分组、计算优先级，并导出 Excel 统计报表。原始文件始终只读，文档内容不会发送给外部 AI。

## 已实现功能

- 导入单个或多个文件，以及整个本地文件夹
- 直接选择 Google Drive、OneDrive/SharePoint 的本地同步文件夹
- 从网页链接抓取正文并在本机分析
- 读取 PDF、DOCX、XLSX/XLSM、CSV、TXT、Markdown、HTML、EML 和常见扫描图片
- 使用随安装包提供的中英文 OCR 模型识别扫描图片；扫描 PDF 无文字层时识别前 3 页
- 提取客户名称、联系人、日期、到期日期、金额、合同编号、项目名称和材料类型
- 提取统一社会信用代码、电话和邮箱，用于客户自动归并
- 检测身份证号、手机号和车牌号等敏感信息
- 通过客户名称、信用代码、电话、邮箱和人工别名匹配客户
- 自动判断合同、发票、报价单、客户证照、身份材料、项目资料等类型
- 根据临近到期、大额、合同、字段缺失、敏感信息和人工标记计算优先级
- 默认按优先级降序、日期降序展示材料
- 生成总览、客户汇总、材料明细、时间分布、待处理与高优先级 Excel 报表
- 可选连接本机 Ollama 模型增强识别；只允许连接 `localhost`/`127.0.0.1`

## 隐私边界

- 原文件不移动、不重命名、不修改。
- 索引数据库位于 Windows 当前用户的应用数据目录。
- OCR 模型随应用依赖提供，识别时无需上传图片或在线下载语言包。
- 本地 AI 端点被限制为回环地址，不能配置成远程 AI 地址。
- 网页导入和云盘同步本身需要联网，但下载后的内容仅在本机分析。
- 文档中的命令或提示一律被当成不可信内容；本地模型输出只接受固定字段，不会执行文档内指令。

更多说明见 [PRIVACY.md](./PRIVACY.md)。

## 开发运行

环境要求：Windows 10/11、Node.js 24 或更高版本。

```powershell
npm install
npm start
```

运行测试：

```powershell
npm test
npm run check
```

生成 Windows 安装包：

```powershell
npm run dist
```

安装包输出到 `dist/`。

## 可选：启用本地模型

基础规则与 OCR 不依赖大模型。需要提高非标准文档的字段识别能力时，可另行安装 Windows 版 Ollama，然后在命令行下载轻量模型：

```powershell
ollama pull qwen2.5:1.5b
```

打开应用的“本地设置”，启用本地模型增强。针对 16GB 内存且无独立显卡的电脑，建议先使用 1.5B 级别的量化模型；处理速度会低于带独立显卡的电脑。

## 使用方式

1. 在“导入材料”中选择若干文件，或在“导入文件夹”中选择档案目录/云盘同步目录。
2. 等待本地提取、OCR、客户匹配和优先级计算完成。
3. 在“材料索引”查看自动排序结果，在“客户分组”查看归并后的客户。
4. 对特殊客户维护人工别名，对重要材料添加人工紧急标记。
5. 在“统计报表”中导出 Excel 工作簿。

## 当前限制

- 旧版 `.doc`、`.xls` 和 Outlook `.msg` 尚未支持；可先另存为 DOCX、XLSX 或 EML。
- 无文字层的扫描 PDF 为控制低配置电脑的等待时间，首版只 OCR 前 3 页。
- 首版通过 Google Drive 和 OneDrive/SharePoint 官方同步客户端接入云端文件，不直接保存云账号令牌。
- 已导入材料会保存导入时的识别结果；修改规则后，需要重新导入变更过的文件才能重新计算全部字段。

## 技术结构

- Electron：Windows 桌面窗口及安全的进程隔离
- Node 内置 SQLite：本地客户、材料和设置索引，无原生编译依赖
- Tesseract.js：打包中英文 OCR 模型
- pdf-parse、Mammoth、ExcelJS：PDF、DOCX 和工作簿文本提取
- Readability + JSDOM：安全提取网页正文，不运行网页脚本
- ExcelJS：生成统计报表
